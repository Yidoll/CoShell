# Design

## Context

CoShell 的初始基线只有 `health` 纵向链路，Vue 工作台通过统一 Backend API 选择 Tauri 或 HTTP transport，四个入口共同调用 `coshell-core`，下层 crate 不得反向依赖应用层。参见 `proposal.md` 的动机与范围，以及本 change 下各能力规格的行为契约。

本变更同时引入远程执行、长期状态、平台秘密存储、流式终端、安全准入和远程备份，属于跨模块且高安全敏感的功能。桌面交付目标是 Windows 与 macOS；HTTP 入口保留等价业务 API，方便未来 Web 工作台复用，但本期发布验收以 Tauri 桌面客户端为主。

## 已实现的 dbx 风格工作台布局

本节根据用户要求参考 `D:/workspace/myutils/dbx/apps/desktop` 的桌面工作台结构和视觉基线编写并已获审核。dbx 的可复用特征是顶部应用工具区与标签区、左侧树形导航、中央编辑/结果工作区、可选右侧工具面板、面板之间的细分隔线，以及由统一设计令牌控制的浅色/深色主题。CoShell 只借鉴这些布局和视觉原则，不复制 dbx 的数据库业务模型、组件代码或资源。

### 顶部直接操作（以最新截图校正为准）

根据 2026-11-17 用户最新标注截图，顶部改为从最左侧排列的紧凑操作栏：“新建连接”“新建命令”“WebDAV 配置”。移除大品牌区域、“统一运维工作台”副标题、重复的工作流标签和页面大标题。

“新建连接”打开当前工作台的连接编辑流程；“新建命令”展开当前会话右侧命令面板并聚焦名称输入，不再挂载第二份独立命令管理页面；“WebDAV 配置”显示现有配置区域并提供“返回会话”。切换配置区域不卸载会话组件，也不重新上传、清空文件路径或命令草稿。隐藏会话显式接收非活动状态并禁止按键/粘贴输入。

### 连接工作台区域

连接工作台采用三列加上下分区的布局：

1. 左侧边栏为连接管理，展示分组、连接名称、连接状态、生产标识和搜索/筛选入口；支持收起、展开和拖拽调整宽度。
2. 中间主区域上方为命令行终端，保留终端标签、连接状态、生产提示和会话上下文菜单；终端高度可拖拽调整。
3. 中间主区域下方为服务器文件夹面板，复用当前 SSH 身份的 SFTP 文件浏览、路径导航、上传下载和右键操作；与上方终端共享当前连接但不共享未确认的写操作。
4. 右侧边栏为命令管理，展示保存命令、搜索和分类；双击命令提交当前会话的风险准入流程。右侧边栏支持收起、展开和拖拽调整宽度。

中间区域是最小可用主区域。窗口变窄时，右侧命令管理优先收起，其次左侧连接管理转为覆盖式面板；终端和文件面板不得被压缩到无法输入或浏览的尺寸。各模块之间保持可见边距和分隔线，不能让按钮或最低一行终端输入被相邻面板遮挡。

### dbx 风格视觉约束

- 颜色使用语义设计令牌，默认采用中性浅色背景、深色文字、低对比边框，深色主题只替换令牌值；危险命令仍以红色文字并辅以图标或标签表达。
- 控件使用统一的紧凑高度、细边框、4–6 像素级低圆角、悬停/焦点/禁用状态和清晰键盘焦点环；不为每个功能重复创建厚重卡片。
- 左右边栏、顶部操作栏、终端工具条、文件面板和 WebDAV 设置采用相同的间距、分隔线和标题层级，功能模块之间保留稳定边距。
- 命令行和文件列表使用适合密集信息的等宽字体或表格对齐；连接名称、生产标识和错误状态使用非颜色辅助信息，满足键盘和屏幕阅读器使用。
- 面板收起、展开、调整宽度和配置切换即时反馈；用户启用减少动态效果时减少动画，状态表达不依赖动画。

### 状态与交互边界

当前活动会话是终端、文件面板和右侧命令执行的共同上下文。三列区域由 `WorkbenchLayout.vue` 的直接子区域组织，连接列表不再嵌入中央网格，命令管理不再嵌入文件区。左右侧栏与中央上下分隔条支持指针拖拽、键盘调整和有界尺寸持久化；收起仅隐藏并禁用焦点访问，不销毁文件/命令组件。服务器指标以左侧“服务器信息”折叠区保留。模态确认的层级高于覆盖式侧栏。配置切换不能绕过任何现有确认。

### 面板尺寸与状态归属

| 区域 | 当前默认值和边界 | 状态与交互 |
| --- | --- | --- |
| 左侧连接栏 | 默认 250px，调整范围 210–380px，并受可用宽度约束 | 保存在本地偏好；宽度小于 800px 时折叠，显式展开为覆盖面板 |
| 右侧命令栏 | 默认 280px，调整范围 240–400px，并受可用宽度约束 | 保存在本地偏好；宽度小于 1100px 时折叠，显式展开为覆盖面板 |
| 中央终端/文件 | 终端默认占分区比例 64%，可调整为 35%–78% | 使用可聚焦分隔条，支持指针和方向键；短窗口保持比例调整有效 |
| 文件及命令编辑 | 折叠时保留当前组件实例 | 目录与草稿仅驻留内存，重新启动应用不承诺恢复未保存内容 |

`WorkbenchLayout.vue` 只管理几何尺寸和布局偏好；`App.vue` 管理配置区域与会话区域切换；`ConnectionsPage.vue` 管理会话标签并传播活动状态；`SessionWorkspace.vue` 关联当前会话的终端、文件和命令操作。浏览器存储不可用时继续使用内存布局，不写入连接资料或备份。断开连接、取消与危险操作确认仍由原业务流程负责。

第 11 节为首轮布局实现，第 12 节依据用户实际截图修复错位、重复操作和状态保留问题。当前验证记录见 `docs/verification/workbench-layout-2026-11-17.md`；真实 macOS 安装与屏幕阅读器验收仍未执行。

## 当前实现与待完成

以下是截至 2026-11-17 的实施状态；后续 Decisions 和各 capability specs 仍是目标设计与验收要求，不因当前限制而降低标准。

- 桌面端已有连接管理、主机指纹确认、密码/私钥/Agent 入口、xterm 和多标签上下文菜单。私钥及可选口令可作为单条秘密保存到系统凭据存储；连接目标变化时拒绝使用旧秘密，启动时恢复 SSH 和 WebDAV 凭据补偿日志。真实 Agent 及 Windows/macOS 凭据存储的完整验收仍待完成。
- 普通连接使用交互式 PTY；生产连接在终端内本地编辑完整命令，风险准入及必要确认后通过独立 exec 执行。生产命令的工作目录和 Shell 状态不跨命令保留，输出在命令结束后返回；远端空闲断线目前在下次执行时发现。该实现尚未满足持久交互式 Shell、Shell integration 及原始模式探测的全部目标。
- 桌面会话输出目前使用消费式轮询，尚未接入带序号的 Tauri Channel/Event 与 HTTP WebSocket。HTTP 的 SSH、概览和备份入口目前明确返回不支持，不能视为跨入口等价。
- 桌面概览已使用独立只读 exec、手动和定时刷新，并区分零值、不可用及陈旧状态；完整指标展示、双 transport 合同和平台验收仍待完成。
- 桌面 WebDAV 已接入服务器响应检查、手动同步、5/10/30/60 分钟及 24 小时自动备份、含连接凭据的备份和事务恢复。新备份使用独立目录清单及完成标记，未知发布可按原操作只读核实。填写口令使用认证加密，口令留空按用户选择上传未加密格式；本地队列始终加密。恢复保留本机主机信任，不自动导入备份指纹；仅浏览和预览不修改本地连接、凭据或同步基准。旧协议临时对象安全清理、旧未知操作完整恢复、跨平台验收和 HTTP 接入仍待完成；已有 WebDAV 凭据时也尚无界面删除凭据并切换目标的流程。
- 2026-11-14 增加终端下方的 SFTP 文件面板和保存命令管理，移除独立系统概览菜单，保留会话指标。保存命令独立 exec 执行并核对保存版本；生产文件变更强制确认。SFTP 文件传输当前上限 16 MiB，文本编辑 1 MiB；覆盖前摘要检查不能消除 SFTP v3 的远端并发写入窗口。
- 备份查看重设计任务 10.1–10.6 已实现并评审：每个 UTC 时间目录内的 `manifest.json`、`connections.pkg`、按需 `credentials.pkg` 和最终 `complete.json` 构成独立恢复单元。清单区分应用/格式版本，卡片区分结构检查与完整校验，异常条目保留可见但禁用恢复。新列表使用 `{ snapshots, nextCursor, scannedCount }`，不依赖旧全局索引；`latest/history/attempt/receipt/probe` 只读兼容。旧版本列表的数组/分页契约缺陷已在 9.1 修复，不再作为新快照的权威发现路径。

## 已实现的备份查看重设计

本节描述用户 2026-11-16 审核并已按任务 10.1–10.6 实施的备份查看设计。剩余旧任务 32 项及其平台验收条件不因本批完成而降低。

- 发布时先持久化带 operation ID 的快照归属，写入独立目录及全部必需文件，完成长度/摘要回读后最后写入 `complete.json`。同名目录或完成标记结果未知时保留未知状态，不认领、覆盖或盲目重试。
- `manifest.json` 只保存非秘密元数据：快照 ID、格式版本、应用版本、创建时间和时区、保护模式、连接/分组数量、凭据是否存在、各必需文件相对路径/长度/摘要。清单不得携带口令、私钥或解密密钥。
- “查看备份”按清单创建时间降序显示卡片。卡片展示应用版本、格式版本、已知大小、加密状态、凭据状态和检查结果；未知大小显示“未知”。状态至少包括待校验、结构完整、缺少清单、清单损坏、缺少完成标记、缺少必需文件、格式不支持、摘要不匹配和暂时不可检查。
- 点击恢复才执行完整下载、摘要/长度校验和按需解密；预览显示本地与备份所有会变更的连接字段、凭据存在状态、分组层级和生产策略。恢复令牌持有已验证的快照内容和本地基准，绑定来源目标及账号，应用时重新检查目标、会话准入和本地快照；取消和预览失败不修改基准。
- 新格式不再依赖根目录 `latest` 才能被发现。旧协议在卡片中标识“旧格式兼容”，只有索引能证明发布且实际负载可访问的条目才能进入恢复，孤立旧对象显示待确认；不自动迁移或删除远端对象。
- 新队列使用系统凭据存储密钥在本地认证加密，操作、规范目标、账号和目录与密文绑定；错误密钥和目标变化拒绝读取或发送。进程中断后的 `running/unknown` 不自动上传，用户可通过原操作的“核实结果”执行完整 artifact 的只读比对，再将确认为完成的操作记为成功。

## Goals / Non-Goals

**Goals:**

- 建立单一的连接、会话、历史、守护和备份领域模型，避免 Tauri 与 Web 各自实现规则。
- 为 SSH 会话提供可取消、有界、可恢复的生命周期和带序号的流式事件。
- 在命令发送前完成核心层风险准入，并对生产连接提供不可绕过的一次性确认。
- 使用操作系统安全存储保护本地秘密，并对 WebDAV 备份实施客户端认证加密和事务式恢复。
- 使 Windows/macOS 共享数据格式、协议、测试夹具和大部分实现，仅在平台适配层分叉。

**Non-Goals:**

- 不实现独立 FTP/FTPS、端口转发、跳板机编排、多人共享或云端账号同步；根据 2026-11-14 用户确认，文件管理使用现有 SSH 的 SFTP。
- 不承诺解析任意 Shell 或全屏交互程序内部的每一次按键；无法确认命令边界时采用未知风险流程并明确提示覆盖范围。
- 不把命令历史、终端输出或 WebDAV 凭据纳入连接备份。
- 不在首期提供 Linux 桌面安装包，也不针对 Windows PowerShell 远程语法提供完整危险规则；未知语法在生产环境按保守策略处理。

## Decisions

### 1. 保持 core 编排并新增三个下层能力 crate

新增以下下层 crate，并同步更新 workspace、架构文档和架构守卫：

- `coshell-storage`：SQLite schema/migration、连接元数据、主机指纹、历史、设置和事务快照；不访问网络，不依赖 core。
- `coshell-shell`：Shell 命令分词、风险规则、脱敏和规则版本；不发送命令，不感知 UI。
- `coshell-backup`：版本化备份 envelope、认证加密、WebDAV 客户端、ETag/条件更新和恢复包校验；不决定业务冲突策略。

`coshell-types` 持有稳定 DTO 和错误 envelope；`coshell-platform` 持有 Windows Credential Manager、macOS Keychain、应用目录和剪贴板等宿主原语；`coshell-drivers` 持有 SSH、PTY、远程 exec 通道和系统指标采集；`coshell-core` 组合这些能力并执行授权、状态机和事务流程。

选择该拆分而不是把持久化、Shell 规则和 WebDAV 全部放入 core，是为了保持实现可单测、依赖单向和入口无关。没有选择为每个 feature 建独立服务进程，因为首期是本地桌面应用，进程拆分会增加凭据传递和生命周期复杂度。

### 2. 使用 Rust 异步 SSH 适配器和独立通道

在 `coshell-drivers` 中定义 `SshConnector`、`TerminalChannel` 和 `RemoteExec` trait，以 Rust 原生异步 SSH 实现作为默认适配器。实现必须支持密码、私钥、SSH Agent、主机密钥回调、PTY resize、取消和超时。

交互终端使用长期 PTY channel；服务器指标使用同一连接身份下的独立短生命周期 exec channel，不向 PTY 注入命令。连接池只复用经过主机校验且身份相同的底层会话，并对每个通道设置并发和空闲上限。

优先评估纯 Rust 异步实现（如 `russh`），避免 Windows/macOS 打包额外原生 SSH 库。若 SSH Agent 在目标平台的兼容性验证不满足规格，则保持 trait 不变并替换适配器，而不改变 core 或 transport 契约。未选择调用系统 `ssh` 可执行文件，因为其版本、提示交互、配置继承和跨平台输出难以形成稳定协议。

### 3. 终端采用 xterm.js，后端输出使用有序事件流

Vue 端使用成熟终端渲染引擎承载 ANSI、选择、复制粘贴和尺寸计算，不自行实现终端解析。后端以 `SessionEvent { session_id, sequence, kind, payload }` 输出数据、状态和错误事件：Tauri 使用 Channel/Event，HTTP 使用 WebSocket；两种 transport 映射到同一前端订阅接口。

每个会话维护有界发送队列和环形回滚缓冲。序号由 core 会话监督器生成，客户端忽略重复或过期事件。关闭采用“停止输入 → 取消读取 → 关闭 channel → 释放底层连接引用”的顺序，并设总超时。重连创建新 `session_id`，不复用旧序号，也不自动重放输入。

未采用轮询 HTTP 输出，因为它增加延迟、重复事件和资源泄漏风险；未自行实现 ANSI 渲染，因为成熟终端语义远超本变更范围。

### 4. 命令提交经过 CommandIntent 准入，原始交互明确降级

普通 Shell 提示符下，前端维护待提交命令缓冲区；按 Enter 后形成包含连接快照、命令文本、会话标识和客户端 nonce 的 `CommandIntent`，先调用 core 的 `prepare_command`。生产连接由客户端完成整行编辑与提交前确认，审批前不将命令字节逐键发送到远端；因此远程 Shell 的原生 Tab 补全、历史行编辑等能力在该模式下受限。用户于 2026-11-10 明确选择该行为。core 使用 `coshell-shell` 返回 `safe`、`dangerous` 或 `unknown`，以及稳定类别、规则版本和脱敏摘要。

- `safe`：返回短时、单次、绑定命令哈希和连接版本的发送许可。
- `dangerous + production`：返回 `confirmation_required`，用户确认后 core 签发一次性许可。
- `dangerous + non-production`：保留红色提示；除非连接启用“始终确认”，可直接签发许可。
- `unknown + production`：与危险命令相同，必须确认。

实际发送必须携带许可；core 再次核对命令哈希、连接、生产标识、规则版本、过期时间和是否已使用，从而阻止 transport 绕过。确认和发送使用幂等 operation ID，重复事件只执行一次。

通过 OSC 133 等 Shell integration 辅助识别提示符和命令边界。进入 `vim`、`top` 等原始模式后，后续按键不宣称属于命令守护范围；启动这些程序的 Shell 命令仍经过准入。未选择仅在前端正则匹配，因为它可被 API 调用绕过，也无法绑定确认后的命令内容。

### 5. 危险规则为版本化数据并使用保守解析

`coshell-shell` 先对 POSIX Shell 常见结构进行词法切分，再按命令、参数、重定向、管道、子命令和多行单元应用版本化规则。首期规则覆盖递归/根路径删除、块设备覆盖与格式化、分区修改、关机重启、递归权限/所有权修改等类别。

规则输出不只是布尔值，而是 `RiskAssessment { level, categories, rule_version, display_spans, redacted_digest }`。解析失败不猜测为安全：在生产连接返回 `unknown`。规则更新必须有表驱动测试、误报/漏报夹具和兼容版本说明。

### 6. SQLite 保存非秘密状态，秘密只保存引用

`coshell-storage` 使用单个版本化 SQLite 数据库，初始表包括：

- `connection_groups`、`connections`、`connection_secret_refs`；
- `trusted_host_keys`；
- `command_history` 与搜索索引；
- `app_settings`、`webdav_profiles`、`backup_runs`；
- `schema_migrations`。

连接、生产标识和历史更新使用事务；删除连接前由 core 检查活动会话。秘密以随机稳定 ID 存入平台安全存储，SQLite 只保存引用和秘密类型。日志层统一对 secret DTO、命令敏感 span 和 URL userinfo 脱敏。

历史只在 CommandIntent 通过后创建记录，并在收到 Shell integration 的结束事件时补充退出码/耗时；无法关联时标为未知。敏感提示输入不形成 CommandIntent；疑似秘密参数在进入存储和索引前脱敏。

未采用前端 localStorage/IndexedDB，因为桌面和 Web 后端需要共享事务、一致迁移和秘密引用策略。

### 7. 系统信息使用独立只读采集器和快照 DTO

`coshell-drivers` 根据远程 OS 能力选择只读采集脚本，首期优化 Linux/Unix SSH 目标。采集器读取 `uname`、`/proc`、`df` 等可用来源，解析为带 `Option` 字段、单位和 `collected_at` 的 `ServerOverviewSnapshot`。缺失字段保持 `None` 并携带原因，不用 0 代替。

core 对同一连接的刷新做 single-flight，支持取消、超时和过期结果丢弃。自动刷新仅在概览可见且连接在线时运行；错误不会关闭 PTY 或污染终端状态。

### 8. WebDAV 使用 envelope 加密和条件发布

备份采用版本化 envelope。提供口令时，payload 使用随机数据密钥进行 XChaCha20-Poly1305 认证加密，口令经 Argon2id 派生密钥用于包装数据密钥；留空口令时按用户 2026-11-11 的明确选择使用未加密格式，远端可读取连接信息及连接凭据。界面在同步和启用自动备份前说明该行为。无口令备份的本地持久发布队列仍须使用系统凭据存储中的本地密钥加密，不能将私钥明文写入本地 SQLite。自动备份不保存或上传用户输入的备份口令。

备份包含连接字段、分组、生产标识、主机指纹及已保存的连接凭据。WebDAV 自身凭据、命令历史和终端输出始终排除。

同步先持久化加密的本地操作和快照归属，校验规范化目标与账号后，创建缺失配置目录和 UTC `yyyyMMddHHmmss` 时间目录。上传 `connections.pkg`、按需 `credentials.pkg` 及 `manifest.json`，逐项回读后最后发布绑定清单摘要的 `complete.json`。新快照不写旧 `latest/history`；结果未知时只读核实原操作的全部文件，不认领已有目录、不盲目重发或删除。查看备份通过有界目录发现、清单/完成标记检查及必需包 HEAD 检查生成卡片，每页最多 50 项；只有点击恢复才完整验证摘要和按需解密。旧协议读取仍沿已有 `latest/history` 链定位 `attempt-*`，只用于兼容。

恢复先下载、校验、解密并构建 `RestorePlan`，再显示新增/更新/冲突/跳过项。用户为冲突逐项选择保留本地、使用备份或创建副本。应用前创建本地事务快照，数据库变更与安全存储写入由补偿日志协调；失败时回滚数据库并清理本次新增秘密，无法完全补偿时进入可继续恢复状态并保留诊断。

不使用“最后写入覆盖”，因为多设备会导致静默丢失。未加密模式按用户选择允许远端读取内容，提供口令的模式仍保持客户端加密。

### 9. 稳定错误 envelope 和长任务协议

跨入口错误统一为 `ErrorEnvelope { code, message_key, safe_detail, operation_id, outcome, retryable }`，禁止携带秘密和内部堆栈。连接测试、会话创建、指标刷新、备份和恢复均使用 operation ID；core 保存短期去重状态，重复请求返回已有结果或状态。

长任务状态为 `queued/running/succeeded/failed/cancelled/unknown`，取消是幂等操作。Tauri 与 HTTP 只负责参数/事件映射、身份上下文和传输错误转换，不复制领域判断。

### 10. 前端按工作流拆分而不是继续扩大 App.vue

前端新增路由/工作区状态和以下领域模块：连接侧栏、终端工作区、服务器概览、历史页面、设置/WebDAV。Pinia store 管理可共享状态，composable 管理会话和订阅生命周期，`lib/backend/api.ts` 仍是唯一后端入口；Tauri/HTTP transport 共享 TypeScript 接口。

危险命令视觉使用设计 Token，并同时显示图标/标签，不能只靠颜色。终端、连接和恢复对话框需要键盘操作、焦点恢复、屏幕阅读器名称和 Windows/macOS 快捷键差异测试。

### 11. 参考 dbx 的多面板壳层组织 CoShell 工作流

顶部操作、左右侧栏与中央上下分区由前端壳层统一编排，各业务组件声明内容与事件，布局通过专用槽位组合。连接、终端和文件操作继续调用统一 Backend API；右侧保存命令与顶部“新建命令”使用当前会话同一组件实例。面板宽度、比例和收起状态属于本地界面偏好，不写入连接资料或远端备份。

使用中性背景、细边框、紧凑控件和清晰的危险状态。窄窗口优先收起右栏，再将左栏转为覆盖式面板；显式展开不会挤压中央操作空间。新建命令聚焦名称，未保存草稿存在时阻止重复新建覆盖；危险命令确认独立于可收起面板，保持可见。

## Risks / Trade-offs

新增文件面板复用已认证 SSH 的独立 SFTP subsystem；路径作为协议字段处理，不拼接 Shell。目录、文本和传输均设置大小/数量/时间上限；删除、覆盖、重命名和权限变更在核心层按生产标识执行一次性确认。上传和下载通过宿主文件选择框授权本地文件，文件传输失败或取消不自动重发。保存命令由 SQLite 持久化，双击后经过当前连接相同的命令准入，禁止通过原始终端写入绕过生产确认。

新 WebDAV 快照通过目录内清单、完成标记和必需包检查独立发现；卡片“结构完整”不等于已认证或内容完整校验通过。旧协议只沿已有 `latest/history` 证据读取，不能从孤立目录推断发布成功。发现受 1 MiB/1000 个响应显式上限约束，单条检查超时显示暂不可检查；超限报错，不静默截断。恢复令牌固定已验证内容、来源和本地基准，未加密模式无来源认证，需用户核对凭据替换。

- **[Shell 边界无法覆盖所有交互]** → 使用 CommandIntent、Shell integration 和生产未知风险确认；原始模式持续展示覆盖边界，不宣称绝对防护。
- **[SSH Agent 与密钥格式跨平台差异]** → 以 trait 隔离适配器，在 Windows/macOS 建立真实 Agent/Keychain 集成测试矩阵，失败时不降级为明文秘密。
- **[终端高速输出造成内存或 UI 阻塞]** → 后端有界队列、客户端环形缓冲、批量绘制和背压指标；超限时保留最新数据并报告截断。
- **[SQLite 与安全存储跨资源事务不可原子]** → 使用补偿日志、稳定 secret ID 和可恢复状态，删除/恢复按可重放步骤执行。
- **[危险规则误报或漏报]** → 版本化规则、夹具测试、unknown 状态和显式审计；产品文案说明守护降低风险但不替代服务器权限控制。
- **[WebDAV 实现差异大]** → 连接测试探测 MOVE、ETag 和锁能力，按能力选择不可变对象策略，禁止无提示的非原子覆盖。
- **[备份口令遗失导致不可恢复]** → 创建时要求重复确认并提供恢复测试；不实现后门或服务端密钥托管。
- **[HTTP 入口扩大攻击面]** → 远程部署前必须增加认证、CSRF/Origin、防暴力破解和连接范围策略；未配置安全策略时仅允许回环地址访问。

## Migration Plan

1. 增加新 crate、DTO、SQLite v1 schema 和空数据迁移，保持现有 `health` 链路不变。
2. 先交付连接管理、平台秘密存储和连接测试；数据格式固定后增加 Windows/macOS 兼容夹具。
3. 增加终端会话与有序事件流，再接入服务器概览和命令历史。
4. 在终端发送路径稳定后启用危险规则与生产确认；上线前默认拒绝没有有效许可的生产危险命令。
5. 最后接入 WebDAV 加密备份/恢复，并以人工创建的空配置开始，不自动上传既有数据。
6. 每阶段保持 feature flag；回滚应用版本时只读保留更高 schema 数据，禁止旧版本破坏性降级。备份格式按版本读取，未知高版本拒绝恢复。

发布前必须在 Windows 10/11 x64、macOS Intel 和 Apple Silicon 完成安装、凭据、SSH、终端、备份恢复测试。数据库迁移先复制测试数据目录验证；WebDAV 使用至少一种标准服务和一种行为受限服务验证降级路径。

## Open Questions

- 自动备份支持 5、10、30、60 分钟及 24 小时间隔；连接变更后防抖仍按任务跟踪。
