# SSH 密码保存

## Purpose

允许用户在首次成功连接 SSH 服务器后决定是否保存密码，并在之后直接连接同一服务器和账号。密码无法使用时，用户仍可手动认证，已打开的会话也可继续使用。

## ADDED Requirements

### Requirement: 首次成功连接后征求保存同意
在支持系统凭据存储的 Windows 和 macOS 运行环境中，系统 SHALL 在同一连接目标首次使用手动密码成功打开 SSH 会话后询问是否保存密码。只有用户确认后系统才可持久化该密码。取消或关闭提示 SHALL 保留已建立会话，并仅记录用户选择，不保留密码。

#### Scenario: 确认保存
- **WHEN** 用户首次使用手动密码成功打开会话并确认保存
- **THEN** 密码存入 Windows Credential Manager 或 macOS Keychain
- **AND** 连接资料只保存凭据引用及非秘密状态

#### Scenario: 取消保存
- **WHEN** 用户取消或关闭首次保存提示
- **THEN** 当前会话可继续使用，下次连接仍需输入密码
- **AND** 后续常规连接不重复弹出首次保存提示

#### Scenario: 未完成认证
- **WHEN** 认证失败、连接被取消或主机身份未通过校验
- **THEN** 系统不提示保存，也不持久化本次密码

#### Scenario: 保存失败
- **WHEN** 用户确认保存，但系统凭据写入未成功
- **THEN** 界面说明密码尚未保存，当前会话仍可使用，之后可以手动认证

### Requirement: 自动使用与当前目标绑定的密码
系统 SHALL 在下次打开同一密码认证连接时使用已保存的密码，且 MUST 按现有规则校验主机指纹。凭据 MUST 与连接标识、主机、端口、用户名及认证方式匹配。保存的密码 MUST NOT 通过配置读取接口、连接结果、日志或界面回显。

#### Scenario: 重启应用后连接同一目标
- **GIVEN** 此连接已保存密码
- **WHEN** 用户重启应用并再次打开同一连接
- **THEN** 系统从凭据存储读取密码，用户无需重新输入
- **AND** 主机指纹未知或变化时，系统按现有规则处理后才可发送认证信息

#### Scenario: 更改连接目标或认证方式
- **WHEN** 用户改变连接的主机、端口、用户名或认证方式
- **THEN** 系统不向修改后的目标使用原连接密码
- **AND** 修改后的密码认证目标可再次按首次连接流程询问保存

### Requirement: 已保存密码不可用时可手动连接
系统 SHALL 区分凭据缺失或不可读取、密码被 SSH 服务器拒绝及其他连接失败。已保存密码不可用时 SHALL 提供手动输入入口。系统 MUST NOT 自动反复尝试已被服务器拒绝的密码，且仅在新密码认证成功并获得用户同意后替换已保存密码。不支持持久凭据的运行入口 SHALL 继续提供原有手动密码流程并明确说明能力状态。

#### Scenario: 已保存密码被服务器拒绝
- **WHEN** 服务器拒绝已保存的密码
- **THEN** 界面提示手动输入，本次流程不会自动重试旧密码
- **AND** 通过新密码成功打开会话后可确认替换，取消不会写入新密码

#### Scenario: 系统凭据不可读
- **WHEN** 系统凭据缺失或暂时不可用
- **THEN** 用户仍可手动连接，已有连接资料可继续使用

### Requirement: 沿用连接备份的凭据保护规则
系统 SHALL 将已保存的 SSH 密码作为连接凭据纳入现有 WebDAV 备份及恢复，沿用口令可选的规则。未保存的密码 MUST NOT 纳入备份，清单和预览 MUST NOT 显示密码。恢复到本机后，密码 SHALL 由平台安全凭据存储管理。

#### Scenario: 备份并恢复已保存密码
- **GIVEN** 某连接已经保存密码
- **WHEN** 用户创建备份并选择恢复该连接及其凭据
- **THEN** 有口令的备份将密码放在加密负载中，留空时界面在上传前说明未加密备份包含已保存的连接凭据
- **AND** 恢复后凭据仅用于与备份中目标一致的连接，预览只显示凭据状态
