# CoShell 0.1.1 技术设计

## Context

`WebDavSettings.vue` 已能将表单和新密码一起提交。`webdav_config::save_profile` 先以 `CredentialTargetChanged` 拒绝已有凭据的配置变更，再以 `InvalidInput` 拒绝同时提交密码和配置字段。现有凭据协调器支持新建配置和替换同一配置的密码，但后者只替换凭据引用。两个保存限制都需处理，才能在一次提交中更换账号。

`DesktopRuntime::open_ssh_with_saved` 已能读取系统存储中的私钥，密码分支只接受手动提交的密码。连接备份按引用导出凭据，`restore_secrets.rs` 已识别 `password` 类型。当前 Axum 只提供健康检查，HTTP 适配层已有明确的不支持路径。

## Goals / Non-Goals

- 让共享核心统一管理配置和凭据的更新，在中断后可以确认结果。
- 将 SSH 密码保存决定绑定到已完成认证的会话。界面只获取状态和操作标识。
- 复用系统凭据存储、已有连接资料和备份格式。本变更不新增远程 HTTP 凭据入口，也不修改 SSH 私钥或 Agent 的流程。

## Decisions

### WebDAV 配置与新凭据一起提交

`coshell-core` 在现有秘密操作锁下读取已保存配置、判断目标是否变化并校验输入。没有新密码时，只有目标未变或从未保存过密码才允许仅提交配置字段。界面根据返回的稳定错误标识 `WEBDAV_PASSWORD_REQUIRED` 提示补填密码。涉及新密码的保存复用 `secret_compensation` 和 `webdav_secret_receipt`，先记录待写入项，再写入系统凭据，最后由 `coshell-storage` 在同一个 SQLite 事务发布配置字段、凭据引用和操作回执。旧凭据在提交完成后清理。若只移除原拦截条件，分开更新可能导致用户看到新用户名却仍关联旧密码。

`WebDavSettings.vue` 通过 `backend/api.ts` 提交现有配置、可选新密码和操作标识。配置读取只返回 `hasCredential`。确认提交失败时允许用户修正并重新保存。提交结果未知时先按原标识查询回执，返回已提交、待清理、未提交或暂不可确认的状态。已提交的同一操作不重复写入，操作标识不能用于不同保存请求。后续检查和备份应在同一可见配置版本中读取目标及对应秘密，避免并发更换时混用两套数据。独立的自动备份间隔设置继续由现有入口管理。

### SSH 由已认证会话发起保存确认

打开连接时，`DesktopRuntime` 根据当前连接查询凭据状态。存在绑定匹配的密码且用户未指定手动输入时，从系统存储读取，在现有主机指纹校验之后用于认证。首次手动密码认证并成功打开会话时，核心在内存中暂存本次已认证的密码，向前端返回可选、短时且一次性的保存令牌。令牌与会话、连接标识和目标绑定。确认接口只接收令牌及操作标识，不重新接收密码。核心在确认时复查连接目标，结束后释放秘密。取消、关闭提示、断开会话、连接取消或令牌过期均释放暂存秘密。同一令牌重复确认按原操作结果处理。

在 SQLite 中使用非秘密状态记录同一连接目标已经取消首次提示。取消后保留当前会话，下次仍需输入密码且不弹首次提示。没有已存密码也没有取消记录的旧连接，在下一次成功打开时按首次流程处理。系统凭据读失败或服务端明确拒绝已存密码时，返回可区分的原因并提供手动输入。网络错误和主机身份错误仍按原流程报告。一次连接流程内不会再次自动尝试被拒绝的密码，手动密码通过认证后可以确认替换不可用的已存密码。

### 凭据绑定及入口边界

`coshell-core` 复用凭据协调器管理 `password` 类型，`coshell-platform` 在 Windows 和 macOS 分别使用现有系统存储适配。按连接标识、主机、端口、用户名、认证方式校验凭据。连接修改导致目标变化或删除时，旧凭据引用失效并走现有待清理机制。普通复制连接不继承密码，备份恢复按已确认的恢复计划及备份连接目标校验后重建引用。若持久化需要新字段，只迁移非秘密的提示状态或绑定元数据，保留旧的连接和备份数据。

`SessionWorkspace.vue` 只通过 `backend/api.ts` 调用，Tauri 命令映射共享核心的状态查询、已存密码认证与保存决定。`types.ts` 定义保存令牌及状态契约，稳定区分凭据不可用、认证被拒及持久凭据能力不可用。HTTP 适配层与 API 签名同步，当前版本返回不支持，Axum 不暴露远程凭据接口。其他入口中已有的手动认证继续可用。

## Risks / Trade-offs

- 系统存储与 SQLite 分别提交。使用日志、回执和恢复流程处理两次写入之间崩溃、响应丢失及旧凭据清理失败。
- 确认对话框打开时连接可能被修改或删除。保存时在锁内复查目标及会话，失效令牌不能绑定到另一连接。
- 未填写备份口令时，已保存密码会随现行格式写入未加密备份。创建备份前提示实际包含范围，预览、日志和接口状态仅展示非秘密信息。

## Migration Plan

兼容既有 WebDAV 配置、系统凭据、连接资料和备份格式。新增元数据采用可缺省的迁移，旧记录按无保存决定处理。升级时先完成已有凭据日志的恢复，再开放配置保存和 SSH 密码保存。验证旧版本对新增元数据及既有 `password` 备份的读取行为，记录可用的回退路径。
