# Shell 客户端功能开关

`coshell-core::feature_flags` 定义分阶段发布的运行时门禁。默认配置全部关闭；调用方必须在执行任何副作用前使用 `run_if_enabled` 检查对应门禁。门禁开启只表示允许进入实际实现，不代表该功能已实现或通过验收；当前没有宿主配置入口，也没有因此开放 Shell 功能。

| 阶段 | Feature | 启用前提 | 回滚边界 |
| --- | --- | --- | --- |
| SSH 连接 | `Connections` | 安全凭据、主机密钥校验、连接超时与测试通过 | 停止新连接和连接变更；保留已保存数据，关闭现有连接须由会话管理器执行 |
| 终端 | `TerminalSessions` | SSH 会话、流式清理、命令准入和生产守护均通过验收 | 拒绝创建新会话；现有会话按关闭流程释放，不能把已有命令重新发送 |
| 系统概览 | `ServerOverview` | 独立只读采集、取消与过期结果防护通过 | 停止新采集，保留最后快照并标记陈旧 |
| 命令守护 | `CommandGuard` | 完整准入、一次性确认、规则和绕过测试通过 | 关闭后不得允许生产会话绕过守护；应同时停止生产命令发送 |
| 命令历史 | `CommandHistory` | 脱敏、保留与删除测试通过 | 停止新记录；不删除既有历史 |
| WebDAV 备份 | `WebDavBackup` | 客户端加密、冲突检测和恢复补偿验证通过 | 停止新备份和恢复；保留现有本地数据及远端已完成备份 |

实际业务入口必须采用这些回滚语义并测试其生命周期；本阶段仅提供门禁原语，尚无持久化配置或业务入口。终端和命令守护存在安全依赖，后续接线必须在 core 的发送边界强制执行，不能仅依赖 UI 隐藏功能。

稳定错误码目录目前包含 `UNSUPPORTED`：门禁关闭或运行时能力不可用时返回，`messageKey` 为 `errors.unsupported`、`outcome` 为 `not_started`、`retryable` 为 `false`，可关联 operation ID，不包含输入或秘密。后续能力应在引入真实错误行为时扩展目录，不得改变已有错误码的含义。
