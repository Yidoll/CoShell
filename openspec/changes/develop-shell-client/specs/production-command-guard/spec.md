# Spec Delta

## Purpose

定义危险 Shell 命令的统一风险判定、红色视觉提示与生产环境执行确认机制，在不伪造绝对安全承诺的前提下降低误执行破坏性操作的概率。

## ADDED Requirements

### Requirement: 生产连接先完成整行编辑
系统 MUST 在生产连接的普通命令输入模式下由客户端编辑完整命令，完成风险准入与必要确认后才将该命令发送到远端；界面 SHALL 告知用户远程 Shell 原生行编辑与 Tab 补全在此模式下受限。

#### Scenario: 生产连接编辑命令
- **GIVEN** 用户正在生产连接的普通命令输入模式编辑命令
- **WHEN** 用户输入、修改或取消尚未提交的命令
- **THEN** 系统不向远端发送该命令的任何字节
- **AND** 输入界面说明远程 Shell 原生行编辑和 Tab 补全的限制

### Requirement: 在发送前判定命令风险
系统 SHALL 在命令离开客户端前对完整提交内容进行风险判定，至少识别递归删除、磁盘格式化或覆盖、分区修改、系统关机重启、递归权限变更及其他配置的危险模式。

#### Scenario: 识别直接危险命令
- **WHEN** 用户输入与危险规则匹配的完整命令
- **THEN** 系统在发送前将命令风险标记为危险并给出命中的风险类别

#### Scenario: 识别复合命令中的危险片段
- **WHEN** 用户提交包含管道、条件、子命令或多行内容的复合命令
- **THEN** 系统分别分析可解析的命令单元
- **AND** 任一单元为危险时整个提交被标记为危险

### Requirement: 危险命令默认显示为红色
系统 SHALL 在命令输入区、提交预览和历史记录中默认使用符合可访问性对比度要求的红色文本或等价危险样式显示危险命令，并同时提供非颜色标识。

#### Scenario: 输入危险命令
- **WHEN** 当前输入从普通命令变为危险命令
- **THEN** 命令文本立即显示为红色危险样式
- **AND** 界面同时显示危险图标或“危险命令”标签

#### Scenario: 用户使用高对比度主题
- **GIVEN** 当前主题无法仅靠红色保证辨识度
- **WHEN** 系统展示危险命令
- **THEN** 系统仍通过图标、文本标签或边框提供可辨识的危险提示

### Requirement: 生产连接执行危险命令前强制确认
系统 MUST 在生产环境连接上执行危险命令前阻止发送，并展示连接身份、生产标识、完整命令或有界预览、风险类别和不可逆影响，直到用户对本次操作明确确认。

#### Scenario: 用户确认生产危险命令
- **GIVEN** 当前连接已标识为生产环境且待提交命令为危险
- **WHEN** 用户在确认界面核对信息并明确确认本次执行
- **THEN** 系统仅发送确认时展示的同一命令内容
- **AND** 确认 Token 在一次发送后立即失效

#### Scenario: 用户取消生产危险命令
- **GIVEN** 生产危险命令确认界面已打开
- **WHEN** 用户取消或关闭确认界面
- **THEN** 系统不向远程会话发送该命令的任何部分

#### Scenario: 确认后命令内容发生变化
- **GIVEN** 用户已确认一条生产危险命令
- **WHEN** 命令文本、连接或生产标识在发送前发生变化
- **THEN** 原确认失效并重新执行风险判定与确认流程

### Requirement: 非生产连接保留危险视觉提示
系统 SHALL 在非生产连接上继续以红色危险样式展示危险命令；默认不强制生产级二次确认，但允许用户为该连接启用始终确认策略。

#### Scenario: 非生产连接提交危险命令
- **GIVEN** 当前连接未标识为生产环境且未启用始终确认
- **WHEN** 用户提交危险命令
- **THEN** 系统保留红色危险提示并按正常提交动作发送命令

### Requirement: 无法可靠解析时采用保守策略
系统 MUST 将无法可靠还原完整命令边界的生产环境提交标记为未知风险并要求确认；对于全屏交互程序中的原始按键，系统必须明确展示守护覆盖范围而不得声称已完成命令判定。

#### Scenario: 生产命令边界不明确
- **GIVEN** 当前连接为生产环境
- **WHEN** 系统无法可靠确定即将提交的完整命令
- **THEN** 系统阻止直接发送并以未知风险要求用户确认

#### Scenario: 进入原始交互模式
- **WHEN** 终端进入无法按命令行判定的全屏或原始输入模式
- **THEN** 系统持续展示“命令守护不覆盖当前原始按键”的状态提示
- **AND** 启动该程序的原始 Shell 命令仍经过风险判定

### Requirement: 所有入口使用同一风险决策
系统 SHALL 在 `coshell-core` 业务边界执行最终风险准入，Tauri 与 HTTP 入口不得绕过或各自维护不同的危险规则；风险结果必须包含规则版本和稳定类别。

#### Scenario: 绕过前端直接调用入口
- **GIVEN** 请求通过 Tauri Command 或 HTTP API 提交命令
- **WHEN** 核心判定该命令在生产连接上为危险且没有有效确认
- **THEN** 两种入口均返回相同的“需要确认”错误码和风险摘要
- **AND** 命令不会发送到远程主机

### Requirement: 守护事件可审计但不泄密
系统 SHALL 记录危险判定、确认、取消和拒绝事件的时间、连接标识、规则版本与脱敏命令摘要，不得在审计日志中写入秘密或完整敏感参数。

#### Scenario: 生产危险命令被取消
- **WHEN** 用户取消生产危险命令
- **THEN** 系统记录取消事件和脱敏风险摘要
- **AND** 审计事件不包含密码、Token 或私钥内容
